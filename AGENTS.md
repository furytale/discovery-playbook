# Repository writing guidance

English is the canonical language for committed documentation, future additions and revisions, diagram text, tables, examples, and the related article. Russian instructions or source notes do not by themselves change the output language. A different language edition requires an explicit owner request. For an article written elsewhere, carry these language and voice requirements into its separate brief; this file governs only this repository.

Keep the five-part Core and the three application patterns. DBR is conditional flow control. Do not add frameworks, compulsory process stages, or role hierarchies without an agreed reason and scope.

Use natural, direct English with consistent US spelling. Preserve the mechanism being explained, decision authority, conditions, evidence limits, and the status of examples. Keep conditional options conditional and prohibitions explicit. Translation work must not introduce methodological changes. Do not turn the evolving practitioner playbook into a claim of a proven universal method.

Keep private transcripts, client details, internal retrospectives, and execution briefs out of the repository and public reports.

Preserve stable anchors. When editing, check affected links, table relationships, and Mermaid meaning and rendering. Report checks honestly, distinguishing local previews from actual GitHub rendering. Keep generated review artifacts outside the repository.

Do not push, merge, publish releases, or rewrite history without an explicit request. Preserve unrelated work and stage only intended files.
